### 1. 타일(격자) 기반 클러스터링

지도 영역(bounds)을 `gridSize × gridSize` 격자로 분할하고, 같은 셀에 속하는 마커들을 하나의 클러스터로 묶는 기법.

**장점**: O(N) 시간 복잡도 — 마커 수에 비례하여 성능이 좋음

```ts
// 각 마커를 격자 셀에 배정
const row = Math.min(
  Math.floor(((marker.latitude - bounds.southWestLat) / latRange) * gridSize),
  gridSize - 1
);
const col = Math.min(
  Math.floor(((marker.longitude - bounds.southWestLng) / lngRange) * gridSize),
  gridSize - 1
);
const key = `${row},${col}`;
```

- 셀 내 2개 이상 → 클러스터 (평균 좌표 사용)
- 셀 내 1개 → 개별 마커로 표시

### 2. 거리 기반 탐욕 병합

이미 존재하는 구별 클러스터들을 좌표 거리 기준으로 재병합. 줌 레벨이 높을수록(더 축소) 병합 반경을 넓혀 더 많은 클러스터가 합쳐지도록 함.

```ts
// 줌 레벨에 따라 병합 반경 조절
const threshold = 0.05 + (zoomLevel - MERGED_CLUSTER_ZOOM_THRESHOLD) * 0.05;

// 앵커 클러스터와의 유클리드 거리로 병합 판정
const dLat = clusters[j].latitude - clusters[i].latitude;
const dLng = clusters[j].longitude - clusters[i].longitude;
if (Math.sqrt(dLat * dLat + dLng * dLng) <= threshold) {
  // 병합
}
```

- O(N²) 복잡도지만 클러스터 수가 ~25개로 적어 문제 없음
- 병합 시 shopCount 기반 가중 평균 좌표 사용

### 3. 줌 레벨별 다단계 클러스터링

카카오맵에서 줌 레벨(level)이 높을수록 축소된 상태. 레벨 구간별로 다른 표시 전략을 적용:

| 줌 레벨 | 모드          | 표시                    |
| ------- | ------------- | ----------------------- |
| ≥ 9     | 병합 클러스터 | 가까운 구 클러스터 병합 |
| 7~8     | 구별 클러스터 | 빨간 동그라미 + 숫자    |
| ≤ 6     | 개별 마커     | 갓차 핀 마커            |

핵심 패턴:

```ts
const isClusterMode = effectiveMapLevel >= CLUSTER_ZOOM_THRESHOLD; // ≥ 7
// 병합은 applyCenterCoords 후 mergeNearbyClusters에서 레벨 체크
```

### 4. CustomOverlay DOM 프로그래밍

카카오맵 CustomOverlay에서 XSS를 방지하기 위해 `innerHTML` 대신 DOM API로 요소를 생성하는 패턴:

```ts
const circle = document.createElement("div");
circle.style.cssText = "display: flex; align-items: center; ...";

const count = document.createElement("span");
count.textContent = String(cluster.shopCount); // textContent는 XSS-safe

circle.appendChild(count);
container.appendChild(circle);
```

- `textContent`는 HTML을 파싱하지 않으므로 XSS 안전
- `yAnchor`/`xAnchor`로 오버레이 기준점 조절 (0.5 = 중앙, 1 = 하단)

### 5. Axios 공급망 공격 (2026년 3월)

2026년 3월 31일, 공격자가 axios npm 메인테이너 계정을 탈취하여 악성 버전을 배포한 사건.

**악성 버전**: `1.14.1`, `0.30.4`
**안전한 최신 버전**: `1.15.2`

공격 방식:

- 악성 `postinstall` 훅이 플랫폼별(macOS/Windows/Linux) RAT(Remote Access Trojan) 설치
- Google Threat Intelligence Group이 북한 연계 위협 행위자 UNC1069로 귀속

**대응 방법**:

```bash
# 악성 버전 설치 여부 확인
npm ls axios

# 안전한 버전으로 업데이트 + 버전 고정
npm install axios@1.15.2 --save-exact
```

**추가 취약점 CVE-2026-40175**: `lib/adapters/http.js` 헤더 처리 로직의 SSRF 취약점

**참고 자료**:

### 6. SemVer 캐럿(`^`) 범위

npm의 버전 문법으로, `MAJOR.MINOR.PATCH` 중 MAJOR를 고정하고 나머지 업데이트를 허용.

| 기호       | 의미             | 예시     | 허용 범위        |
| ---------- | ---------------- | -------- | ---------------- |
| `^` (캐럿) | MAJOR 고정       | `^1.7.9` | `>=1.7.9 <2.0.0` |
| `~` (틸드) | MAJOR+MINOR 고정 | `~1.7.9` | `>=1.7.9 <1.8.0` |
| 없음       | 정확한 버전      | `1.7.9`  | `1.7.9`만        |

```jsonc
// package.json
"axios": "^1.7.9"   // 1.14.1 (악성)도 범위에 포함 — 위험!
"axios": "1.15.2"   // 정확히 이 버전만 설치 — 안전
```

보안이 중요한 패키지는 `--save-exact` 플래그로 버전을 고정하는 것이 권장됨.

### 7. `npm install` vs `npm ci`

|                  | `npm install`                     | `npm ci`                     |
| ---------------- | --------------------------------- | ---------------------------- |
| **용도**         | 개발 중 패키지 설치/추가          | CI/CD, 클린 빌드             |
| **lock 파일**    | 없으면 생성, 있으면 업데이트 가능 | 반드시 있어야 함, 수정 안 함 |
| **node_modules** | 기존 것 위에 덧씌움               | 삭제 후 처음부터 설치        |
| **불일치 시**    | lock 파일을 업데이트              | 에러 내고 중단               |
| **속도**         | 느림 (의존성 트리 해석)           | 빠름 (lock 파일 그대로)      |

```bash
# 로컬 개발
npm install

# CI/CD 파이프라인, Docker 빌드
npm ci
```

`npm ci`는 `package-lock.json`을 100% 신뢰하여 팀 전체가 동일한 버전을 사용하도록 보장.
